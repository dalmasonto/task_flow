# Agent Role Instructions and Project Agent Instructions: Design

TaskFlow #615 (agent role instructions) and #616 (project-wide agent instructions).
Date: 2026-10-06. Owner: dalmas (away; the controller decides within the rulings below).

## Goal

An agent today is a name and a key, and nothing tells it what its role is. After this change:

- Each **agent** carries markdown **role instructions** (role, responsibilities, conventions). A human writes them when linking the agent or later from the dashboard.
- Each **project** carries markdown **agent instructions** that every agent in the project reads. Only project owners and admins (and superusers) can change them.
- The agent reads both through `whoami`. An edit takes effect on the agent's **next `whoami`**, with no new key and no restart.
- Agents can read both blocks but cannot write either.
- The MCP tells agents how to apply them. Precedence, highest first: **the human's direct request, then role instructions, then project instructions, then generic defaults.**

## Decisions

### Rulings (binding, from the controller)

- **R1 whoami shape.** `GET /api/taskflow/agents/whoami` and the MCP `whoami` reply add `"instructions": {"markdown": string|null, "updated_at": ts|null}` and `"project_instructions": {...same}`. The change is additive only, and every existing field stays.
- **R2 fields.** `TaskflowAgent.instructions_markdown: Option<String>` and `instructions_updated_at: Option<DateTime<Utc>>`. `TaskflowProject.agent_instructions_markdown: Option<String>` and `agent_instructions_updated_at: Option<DateTime<Utc>>`. There is no size cap. New generated migrations.
- **R3 writes only through role-gated endpoints.**
  - `PUT /api/taskflow/agents/{agent}/instructions` `{"markdown": string|null}`. Allowed: superuser, project owner/admin, or the linker. This is the same rule as `delete_agent`: non-member gets 404, other member gets 403. Stamps `instructions_updated_at`.
  - `PUT /api/taskflow/projects/{project}/agent-instructions` `{"markdown": string|null}`. Allowed: superuser or project owner/admin (`invite_manager_rank`).
  - Auto-REST create/update cannot write the four fields, and a test proves it.
  - `link_agent` accepts optional `instructions_markdown`.
  - No agent-authed write route exists.
- **R4 reads.** The fields come through the existing scoped auto-REST lists. The FE client types are regenerated.
- **R5 MCP.** The new fields reach the agent and render readably. `instructions.ts` states the precedence and says to call whoami at session start. On reconnect the MCP compares the remembered `updated_at` pair and types one notice: `[taskflow] your role/project instructions were updated — call whoami`.
- **R6 FE.** The link form gets an optional "Role & instructions" editor with preview and templates (Reviewer, Designer, Backend, Frontend). Each row gets an "Instructions" button that opens a dialog, plus a badge. A project "Agent instructions" editor is visible to all; the 403 shows inline. Reuse `MarkdownRenderer`. Pure helpers go in tested `.ts` files.
- **R7 docs.** `documentation/docs/v2.0.0` and `v2_fe/public/llms.txt`. No MCP version bump, no deploy.
- dalmas's earlier decisions: no size cap; #616 sits beside #615 in whoami; no version history.

### Further decisions (this spec)

| # | Decision | Why | Cost if wrong |
| --- | --- | --- | --- |
| D1 | Mark all four columns `#[umbral(privileged, …)]`, **not** `noedit`. | `noedit` is not stripped on the REST JSON path (dynamic.rs:4029-4046). `privileged` is (model.rs:568-583). `noform` would also strip, but it hides the field from admin forms and marks it readOnly in OpenAPI. `privileged` keeps reads and typed writes intact. | If umbral later changes `privileged` semantics, the REST-guard test in Task 1 fails loudly. |
| D2 | Markdown columns have no `max_length`, so the type is `TEXT` on Postgres, plus `widget = "textarea"` for the admin. | dalmas: no size cap. `max_length` would make it `varchar(n)`. | Very large text is accepted. The axum 2 MiB JSON body limit is the practical ceiling (accepted). |
| D3 | A blank or whitespace-only `markdown` (or `null`) **clears** the field (stores `NULL`). Non-blank text is stored verbatim. | "Delete the instructions" needs one obvious gesture. Trimming real content would change what the human wrote. | A user who wanted only whitespace gets `null`, which is harmless. |
| D4 | A **no-op** PUT (normalized value equals stored) does not touch `updated_at`. A clear does stamp it. | `updated_at` drives the MCP "instructions were updated" notice, so a Save with no change must not page every agent. | If it is wrong, one spurious notice per no-op save. |
| D5 | Writes use `QuerySet::update_values` on the two columns, not `Manager::save`. | `save` rewrites the whole row from a read moments earlier and would clobber a concurrent heartbeat's `status`/`last_seen_at`. `update_values` also fires `bulk_post_save` for the dashboard. | None found. |
| D6 | `link_agent` applies `instructions_markdown` **only when it creates the agent**. On a re-link of an existing identity it ignores it and returns `"instructions_applied": false`. The FE then calls the PUT, which enforces the manager rule. | Re-link is open to any active member. Applying instructions there would let a developer overwrite another person's agent instructions and bypass R3. | The FE does one extra call on re-link, which is cheap. |
| D7 | Shared helpers `normalize_markdown` and `instructions_block` live in `taskflow-projects/src/instructions.rs`. | `taskflow-agents` depends on `taskflow-projects`, not the reverse, and both PUTs and whoami need the same shape. | Negligible. |
| D8 | Project PUT: a non-member gets **403** (from `invite_manager_rank`). Agent PUT: a non-member gets **404** (from the delete rule). | Each reuses the existing helper the ruling names, without changing either. | Inconsistent codes between the two endpoints. Neither leaks private data (project ids are not secret to members). |
| D9 | MCP `whoami`: the first content block stays the JSON (the full shape, unchanged keys). When either block has markdown, a **second text block** carries a readable rendering: a precedence line, then "## Your role instructions", then "## Project instructions". | JSON escapes newlines into `\n`, so long markdown is unreadable inside it. Tests and clients that parse `content[0]` keep working. | The markdown is sent twice per whoami (tokens). Acceptable: whoami is called at session start. |
| D10 | Reconnect notice: `startAgentRuntime` keeps one in-memory watcher per runtime (a runtime is per profile and is torn down on a switch). On every stream connect it calls `whoami`. The first connect records a baseline only. A reconnect whose `updated_at` pair differs types the notice once. With no pane, nothing is fetched. A failed `whoami` is logged and keeps the old baseline. Not on the heartbeat path. | Ruling R5. A heartbeat-path check would double the request rate. An edit made mid-session reaches the agent at its next whoami or next reconnect. | The agent learns about a mid-session edit late. The docs say edits apply on the next whoami. |
| D11 | The FE project "Agent instructions" editor lives on the **Connect agents** page (a card below the agents list), not in the Edit Project dialog. | Ruling R6 allows "a better place". That dialog is one uncontrolled form PATCHing auto-REST, which now strips the field. A second save inside it with its own 403 would be confusing. The agents page is where agent setup lives. | Moving one self-contained card component later. |
| D12 | FE keeps a local override map after a save and shows whichever of {row, local} has the later `updated_at` (`latestInstructions`). | `workspace.agents`/`workspace.project` are not refetched after a write (same reason `justLinked` exists). A newer realtime row must not be masked by an older local value. | None found. |
| D13 | Templates are four small "Insert template" buttons, not a dropdown menu. Inserting appends to existing text instead of replacing it. | There is no dropdown primitive (`ui-dropdown` does not exist), and appending never destroys typing. | Visual only. |
| D14 | An agent key on either PUT gets 401/403 (the routes take `CurrentIdentity`, a human session or bearer), and the stored value is unchanged. | Agents must not write (R3). | None found. |
| D15 | The PUT replies are `{"agent_id"\|"project": id, "markdown": …, "updated_at": …}`. Link adds `"instructions_applied": bool`. | The FE needs the stored values to update its overlay without a refetch. | Additive. |

## Architecture

```
Dashboard (v2_fe)                       Backend (umbral/axum)                         MCP / agent
-----------------                       ---------------------                         -----------
LinkAgentCard ──POST /agents/link {instructions_markdown?}──► link_agent (creates → applies)
AgentInstructionsDialog ─PUT /agents/{id}/instructions─────► set_agent_instructions
ProjectInstructionsCard ─PUT /projects/{id}/agent-instructions► set_project_agent_instructions
auto-REST lists (read) ◄──────────────── taskflow_agent / taskflow_project rows (privileged cols stripped on write)
                                        whoami_as_agent ──{…, instructions, project_instructions}──► whoami tool
                                                                                          (JSON + readable block)
                                                                       runtime onConnected → watcher → pane notice
```

## Testing

- **Backend (taskflow-agents, `tests/agent_instructions.rs`):**
  - whoami keeps its five fields and adds null blocks.
  - link with instructions sets them, and whoami returns them.
  - linker edit shows on the next whoami with the same key.
  - admin may edit; another developer gets 403; non-member gets 404.
  - agent key cannot write.
  - no-op keeps `updated_at`; blank clears.
  - re-link by another member does not overwrite.
  - whoami returns project instructions beside role instructions.
- **Backend (taskflow-projects, `tests/agent_instructions.rs`):**
  - owner, admin and superuser may edit (a superuser needs no membership).
  - developer, viewer and non-member get 403.
  - a missing project gets 404 for a superuser.
  - no-op keeps time; blank clears.
  - Unit tests in `instructions.rs`.
- **Backend (`backend/tests/rest_scope.rs`):**
  - a member's REST PATCH of either field (and REST POST of an agent with one) does not change the stored value.
  - REST reads expose the fields.
- **MCP:**
  - `agent-instructions.test.ts`: render, stamp, watcher.
  - `server.test.ts`: whoami passes both blocks through; second block only when present.
  - `instructions.test.ts`: precedence order and session-start rule.
  - `runtime.test.ts`: baseline on first connect, one notice on changed reconnect, none when unchanged, failure keeps baseline, pane-less fetches nothing.
- **FE:** `lib/agent-instructions.test.ts` covers templates, normalize, change detection, insert, snippet, `latestInstructions` and payload. Then `npx tsc -b`, `npx vitest run`, `npm run build`. The ESLint error count must not grow.
- Full: `cargo test --workspace`, `cd mcp && npx vitest run && npx tsc --noEmit`, and the FE suite plus build.

## Rollout

1. Backend first (models, migrations, endpoints). The fields are additive, so every installed MCP keeps working: old MCPs pass the whole whoami body through, so agents on an old MCP already *see* the new blocks as JSON. They just lack the precedence guidance and the reconnect notice.
2. Frontend (`npm run build` is the deploy for dalmas's local view).
3. MCP changes ship in the next MCP release (controller-owned; no version bump in this plan).
4. Docs publish on push.

Migration safety: two new generated migration files (`taskflow_agents/0025_*`, `taskflow_projects/0005_*`) add nullable columns. No existing migration is touched. Each is verified with `cargo run -- migrate` against a copy of the dev DB.
