## Fast path

Use the hosted app first unless you are developing the backend itself:

1. Install the MCP package and run the setup walkthrough (below). `taskflow init` registers the server with your coding agent (Claude Code, Codex, Gemini CLI, Cursor or opencode) and, for Claude Code, can install the activity hooks.
2. Open [https://taskflow.supercodehive.com](https://taskflow.supercodehive.com) and create an account or log in. (Self-hosting? Use your own frontend's URL instead.)
3. Create or select a project and open its **API Base** page.
4. Link an agent profile such as `main`; link a second profile such as `reviewer` when you want a separate review identity.
5. Put the generated profile block into `.taskflow.json` at your repo root — or let `taskflow init --project <id> --token <your user token>` link the agent and write the file for you.
6. Restart your agent and ask it to call `whoami`.

## Install and set up

Linux and macOS, in one step:

```bash
curl -fsSL https://raw.githubusercontent.com/dalmasonto/task_flow/main/scripts/install.sh | sh
```

The script checks for Node.js 20+, installs the package globally (it never uses `sudo`; if npm's global prefix is not writable it tells you how to fix that), then starts `taskflow init`. Arguments after `sh -s --` are passed to `taskflow init`.

Or by hand, on any platform (Windows PowerShell included):

```bash
npm install -g @dalmasonto/taskflow-mcp
taskflow init
```

`taskflow init` asks which agents to set up (the ones found on your machine are pre-selected) and whether to register the server for your user (every repo) or only this project. It shows the exact commands and file edits before applying them, backs up every config file it edits, never overwrites an existing `taskflow` entry, and is safe to re-run. For scripts and CI:

```bash
taskflow init --harness claude,codex --scope user --yes      # no prompts
taskflow init --harness all --scope project --dry-run        # show the plan, change nothing
```

The package installs three commands:

| Command | Purpose |
| --- | --- |
| `taskflow` | Setup CLI: `taskflow init`, `taskflow doctor`, `taskflow mint` |
| `taskflow-mcp` | MCP server the agent client starts over stdio |
| `taskflow-hook` | Optional Claude Code lifecycle hook for activity logging |

## Create `.taskflow.json`

The API Base page shows the raw key once. Store it in `.taskflow.json` at the repo root and keep that file out of git.

```json
{
  "server": "https://api.taskflow.supercodehive.com",
  "project": 1,
  "default_profile": "main",
  "profiles": {
    "main": {
      "agent_id": 12,
      "key": "tfk_REPLACE_ME_main",
      "display_name": "Claude (main)"
    },
    "reviewer": {
      "agent_id": 13,
      "key": "tfk_REPLACE_ME_reviewer",
      "display_name": "Reviewer"
    }
  }
}
```

For local development, use the backend URL your browser can reach, usually `http://localhost:8000`.

## Register the MCP server by hand

`taskflow init` does this for you. If you prefer to do it yourself, or your client is not one `init` knows, the per-client pages under [Agent Setup](./agents) have the exact config. For clients that read `.mcp.json`, place this at the repo root:

```json
{
  "mcpServers": {
    "taskflow": {
      "command": "taskflow-mcp",
      "args": []
    }
  }
}
```

If you are running from this repository instead of the global npm package:

```bash
cd mcp
npm install
npm run build
```

Then point the MCP client at `node` with `args` set to the built `mcp/dist/index.js` path.

## Verify the connection

From the repo that contains `.taskflow.json`:

```bash
taskflow-mcp --check
```

Inside your agent, call `whoami`. A correct response shows the agent id, display name, project id, connection state, and terminal mirror state.

## Use tmux for terminal mirroring

TaskFlow mirrors an agent's terminal automatically when the agent runs inside tmux.

```bash
tmux new -s taskflow-main
cd /path/to/your/repo
claude
```

Use the same pattern for Codex or another MCP-capable agent. If `whoami` reports `mirror.state` as `off`, the agent is still connected; only live terminal streaming is unavailable.

`taskflow-mcp --tmux [target]` is for the special case where you want to mirror a different pane. The optional `--notify-submit` mode types into a live pane and presses Enter, so only enable it for sessions you control.

## Run v2 locally

Backend:

```bash
cd backend
cargo run -- migrate
cargo run
```

Run the migration once after checkout or after schema changes. The default `backend/umbral.toml` uses SQLite and binds to `127.0.0.1:8000`.

Frontend:

```bash
cd v2_fe
npm install
npm run dev
```

The Vite dev server proxies `/api`, `/oauth`, `/media`, `/openapi`, and `/realtime` to `http://localhost:8000` by default. Set `VITE_API_PROXY_TARGET` only when your backend runs somewhere else.

MCP package from the checkout:

```bash
cd mcp
npm install
npm run build
```
