## Install

```bash
npm install -g @dalmasonto/taskflow-mcp
taskflow init --harness claude
```

`taskflow init` registers the MCP server with Claude Code and offers to install the activity hooks, so the **Add `.mcp.json`** and **Optional hooks** steps below are only needed if you set things up by hand.

## Link a profile

Open your TaskFlow project, go to **Connect agents**, and link a `main` profile. For review work, link a separate `reviewer` profile. Save what the page shows into `.taskflow.json` at the repo root: the whole file for the first agent, or just the new profile entry (the **Add to existing .taskflow.json** tab) when the file already exists.

```json
{
  "server": "https://api.taskflow.supercodehive.com",
  "project": 1,
  "default_profile": "main",
  "profiles": {
    "main": {
      "agent_id": 12,
      "key": "tfk_REPLACE_ME_main",
      "display_name": "Claude (main)"
    },
    "reviewer": {
      "agent_id": 13,
      "key": "tfk_REPLACE_ME_reviewer",
      "display_name": "Claude (reviewer)"
    }
  }
}
```

Add `.taskflow.json` to `.gitignore`.

### Which `server`?

`server` is the TaskFlow **API** your agent talks to, and the Connect agents page fills it in:

| Using | `server` |
| --- | --- |
| The hosted app (`taskflow.supercodehive.com`) | `https://api.taskflow.supercodehive.com` |
| A local backend | `http://localhost:8000` |
| Your own deployment | Your backend's URL, e.g. `https://api.taskflow.example.com` |

Do not use the web app's address (`https://taskflow.supercodehive.com`): it serves the dashboard, not the API, and the MCP will fail to authenticate.

<Callout type="info">
With the hosted app, your tasks, chat, attachments and **Claude's mirrored terminal output** are stored on our server. If your code must stay on your own machines, [self-host the backend](../self-hosting) and point `server` at it — nothing else in this guide changes.
</Callout>

## Add `.mcp.json`

Place this at the repo root:

```json
{
  "mcpServers": {
    "taskflow": {
      "command": "taskflow-mcp",
      "args": []
    }
  }
}
```

Start Claude Code from that repo. The MCP server reads `.taskflow.json`, connects as the selected profile, and registers the live session.

## Optional hooks

Copy the hooks block from `mcp/.claude/settings.example.json` into your project's `.claude/settings.json`.

```json
{
  "hooks": {
    "SessionStart": [{ "hooks": [{ "type": "command", "command": "taskflow-hook" }] }],
    "PreToolUse": [{ "matcher": "*", "hooks": [{ "type": "command", "command": "taskflow-hook" }] }],
    "PostToolUse": [{ "matcher": "*", "hooks": [{ "type": "command", "command": "taskflow-hook" }] }],
    "Stop": [{ "hooks": [{ "type": "command", "command": "taskflow-hook" }] }],
    "Notification": [{ "hooks": [{ "type": "command", "command": "taskflow-hook" }] }]
  }
}
```

The hook is best-effort. If `.taskflow.json` is missing or the backend is unreachable, it exits without blocking Claude Code.

## Terminal mirroring

Run Claude Code inside tmux when you want the dashboard to show its terminal:

```bash
tmux new -s claude-main
cd /path/to/repo
claude
```

Ask Claude to call `whoami`. A healthy setup shows the selected profile, the project id, an active connection, and the mirror state.

## Review profile

To start a reviewer terminal:

```bash
export TASKFLOW_PROFILE=reviewer
claude
```

Or let Claude ask which profile to use and then call `select_profile`.
