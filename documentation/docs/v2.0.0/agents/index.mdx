## Shared setup

Every MCP-capable agent uses the same TaskFlow v2 credential model:

1. Install `@dalmasonto/taskflow-mcp` and run `taskflow init` — it registers the server with Claude Code, Codex, Gemini CLI, Cursor and opencode for you (see [Getting Started](../getting-started)). The pages below are the manual equivalent, and the only path for clients `init` does not know yet.
2. Link an agent profile from the project's **Connect agents** page.
3. Put the generated profile in `.taskflow.json` at the repo root (the whole file for the first agent, just the profile entry for the next). Its `server` is the TaskFlow API — or your own backend if you [self-host](../self-hosting).
4. Configure the agent client to start `taskflow-mcp` (step 1 already did this for the clients it supports).
5. Run the agent inside tmux when you want live terminal mirroring.
6. Ask the agent to call `whoami` and confirm the profile, project, connection, and mirror state.

## Profile selection

Use one profile per live terminal. Two terminals using the same profile are the same TaskFlow agent: one direct-message inbox, one unread cursor, and one session identity.

When a repo has several profiles, the agent may need to call `select_profile`. It should ask the human first and never guess. Set `TASKFLOW_PROFILE=reviewer` when you want a process to always use a specific profile.

## Expected agent behavior

Agents should treat TaskFlow as the source of truth:

- Call `whoami` at startup.
- Use `list_tasks` before creating duplicate work.
- Claim real work and move it to `in_progress`.
- Log meaningful activity, especially after long or risky steps.
- Check messages regularly and mark handled messages read.
- Move completed work to `partial_done` for review.
- Use `report_review` from a reviewer identity.
