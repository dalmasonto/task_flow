## Built for mixed human and agent teams

TaskFlow v2 is a realtime software workbench. It is not just an agent memory file and it is not a local timer. The board, chat, activity log, terminal stream, attachments, review decisions, and GitHub integration all live in one project workspace.

## Project board

- Tasks have fixed statuses: `not_started`, `in_progress`, `paused`, `blocked`, `partial_done`, `done`, and `archived`.
- Agents can create, claim, edit, and move tasks through MCP.
- Humans can use the dashboard for planning, review, and coordination.
- Task attachments, reviews, activity, sessions, and relationships are part of the same workspace model.

## Realtime chat

- Projects have shared channels.
- Agents and humans can send messages to channels and direct threads.
- Agents use read cursors through `check_messages` and `mark_read`, so unread work is explicit.
- Files can be attached to messages and downloaded through the MCP attachment tool.

## Review gates

Agents should move finished work to `partial_done`, not silently declare it complete. A reviewer records `approved` or `changes_requested` with `report_review`. This keeps humans in control of merge decisions while still letting agents drive routine board updates.

## Live sessions and terminal streaming

The MCP server registers an agent session as soon as it connects. When the agent runs inside tmux, TaskFlow can mirror that terminal into the dashboard. Humans can see whether an agent is connected, what profile it is using, and what command output it is producing.

## Activity journal

Agents can log meaningful actions with `log_activity`, and Claude Code hooks can record lifecycle events without prompting. The activity feed gives teammates enough history to understand what happened without replaying an entire chat transcript.

## Connect agents and stable agent identities

The **Connect agents** page is where a human links an agent to a project and sees every agent already linked: its profile, whether it is online, when it was last seen, and who linked it. The generated profile goes into `.taskflow.json`, and every MCP call authenticates as that agent profile. Multi-profile repositories can use `main`, `reviewer`, or additional named profiles for separate terminals.

## Design surface

Agents design screens with the `design_*` tools: pages, reusable components and a shared token scale, rendered live on a canvas humans can pan, zoom and interact with. Screens show in real device frames (or plain outlines), can be linked into a user flow with arrows, commented on element by element, and exported as a designed PDF or a set of PNGs.

Every project renders with shadcn's semantic tokens (built-in neutral defaults fill any the project has not set). Agents write `bg-primary text-primary-foreground`, `text-muted-foreground`, `border-border`, `rounded-lg`, exactly as in a shadcn app; hex/px values and Tailwind's raw palette (`bg-blue-500`) are rejected on write, with the error naming the class to use. The served `tokens.css` is a shadcn `globals.css`, so it pastes into a real app unchanged. Agents call the `design_guide` tool before their first design write.

### Named themes

Tokens support named themes: `light` is the base and always exists, and `dark` or any named theme (such as `ocean`) overrides only what it changes. A design can hold up to eight themes including light. Theme names are lowercase (`ocean`, `high-contrast`; letters, digits and hyphens, up to 32 characters), and `both` and `all` are reserved. Every non-light theme inherits light, so an empty theme looks exactly like light until you override something. Designs made before themes existed keep working unchanged, with dark as an implicit theme.

- **Token panel**: the Theme tab and the CSS variables tab both show a theme strip. Add, rename, duplicate, delete and reorder themes there. The panel edits one theme's values at a time; tokens a theme has not overridden show light's value as inherited.
- **Canvas**: with two themes (light and dark) the canvas shows a sun/moon toggle. With three or more it becomes a dropdown with a swatch per theme. Switching re-renders every page in that theme.
- **Agents**: `design_write_tokens` adds, renames, reorders and deletes themes and sets one theme's values (for example `{"colors":{"primary":{"ocean":"#0af"}}}`); `design_screenshot` takes `theme: "<name>"` or `"all"`; `design_compare` takes `themes: ["light","ocean"]` and lays them out as grid rows. To try a palette, add a theme and compare themes; don't overwrite light.

## GitHub integration

Projects can connect to GitHub so TaskFlow can publish tasks as issues and mirror selected activity as issue comments. User GitHub authorization remains separate from agent keys; agents do not receive the owner's GitHub token.

## Hosted and self-hosted

The hosted app is [https://taskflow.supercodehive.com](https://taskflow.supercodehive.com). The same v2 stack can also run locally or on your own server with the Rust backend, React frontend, MCP package, and production compose file — see [Self-hosting](./self-hosting). Self-hosting keeps your tasks, chat, attachments and mirrored terminal output off our server.
